# ECMWF Thailand Rainfall Forecast Dashboard

Minimal public dashboard for the GISTDA disaster workflow.

## User experience

The public user does **not** enter an email or password.

The page has:
1. One `RUN FORECAST` button.
2. Real processing status.
3. PART A only: 24-Hour Accumulated Precipitation, Day 1–Day 10.
4. The original PNG map style from the existing ECMWF notebook.
5. Satellite footprints and ground tracks retained on every PART A map.
6. One link to Google Drive for all additional 12h / 6h / 3h products.

## Files

- `app.py` — Streamlit web dashboard.
- `forecast_runner.py` — job lock, status reporting, engine launcher.
- `forecast_engine.py` — adapter where the existing notebook processing code is integrated.
- `requirements.txt` — Python packages.
- `.gitignore` — prevents secret/runtime files from being committed.

## Important security rule

Never put Gmail passwords, service-account private keys, API keys, or tokens in GitHub.

Use:
- Google Cloud Secret Manager, or
- Streamlit secrets / environment variables.

The web user must never receive the backend credential.

## Environment setting

Set the shared Drive viewer URL:

```bash
GOOGLE_DRIVE_URL="https://drive.google.com/..."
```

On production, use the platform secret/environment configuration.

## Run locally

```bash
pip install -r requirements.txt
streamlit run app.py
```

## Map files expected by Dashboard

The existing notebook already creates filenames similar to:

```text
ecmwf-24hr-day1-YYYYMMDDtHHMM-YYYYMMDDtHHMM-Local-time.png
...
ecmwf-24hr-day10-YYYYMMDDtHHMM-YYYYMMDDtHHMM-Local-time.png
```

These files should be written to `outputs/`.

The Dashboard does not redraw the map. It displays the PNG generated by the original forecast code, therefore satellite footprints, ground tracks, rainfall colors, labels and map style are preserved.

## Concurrency

`forecast_runner.py` creates a lock file while a run is active. A second visitor cannot start another duplicate forecast job; they see the current processing state instead.
